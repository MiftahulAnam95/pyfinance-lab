Siap Presentasi

Latih demo dan jawaban untuk kemungkinan tanya jawab.

TUJUAN BELAJAR

Menyampaikan masalah, demo, dan keterbatasan dengan bukti dari kode.

SEBELUM MULAI

Coba satu sesi lengkap program atau simulator; cek format dan durasi dengan dosen.

Narasi yang sederhana

Mulai dari pengeluaran kecil yang sering terlupa. Lalu perlihatkan cara mencatat pemasukan dan pengeluaran, bukti saldo, dan di mana program menyimpan data selama sesi. Akhiri dengan keterbatasan, bukan klaim berlebihan.

Bukan prediksi soal ujian

Pertanyaan di sini adalah bahan latihan, bukan daftar soal yang pasti keluar. Durasi dan susunan pembicara dapat diganti. Saat tidak tahu, sebutkan batas yang kamu pahami lalu jelaskan cara mengeceknya.

Naskah sesuai durasi

Perkiraan waktu, bukan aturan. Ganti “kami” dengan “saya” bila presentasi sendiri.

±30 detik

Pengeluaran kecil sering terlupa. Karena itu kami membuat pencatat keuangan di terminal agar mahasiswa bisa mencatat uang masuk dan keluar serta melihat sisanya. Sebagai contoh, dari uang saku Rp150.000 setelah makan Rp25.000, saldo tercatat Rp125.000. Empat file membagi pekerjaan antara menu, pencatatan, laporan, dan tampilan. Versi ini hanya menyimpan data selama sesi.

±2 menit

Pembukaan: “Pernah merasa uang saku cepat habis padahal tidak ingat belanja apa saja? Kami mulai dari masalah itu. Tujuan proyek ini bukan membaca rekening, tetapi membantu mencatat transaksi yang kita masukkan sendiri.”

Cara kerja: “Pengguna memilih menu dan mengetik nominal bulat. Program menolak titik ribuan saat input, tetapi menambahkan titik ketika menampilkan angka. Untuk pengeluaran, kita menuliskan kategori seperti Makan. Setiap catatan masuk ke sebuah daftar yang tetap tersedia selama menu diulang.”

Demo: “Saya pilih 1 lalu ketik 150000. Berikutnya saya pilih 2, ketik 25000 dan Makan. Pada pilihan 3, saldo adalah Rp125.000. Menu 4 menunjukkan dua catatan; menu 5 hanya menampilkan pengeluaran Makan sebesar Rp25.000.”

Penutup: “main mengatur pilihan, pencatat memvalidasi dan menghitung, laporan merangkum, dan tampilan menyeragamkan format. Saat keluar, data tidak disimpan. Penyimpanan ke file bisa menjadi tahap selanjutnya. Silakan bertanya tentang bagian yang ingin ditelusuri.”

±5 menit

0:00–0:45 · Pembukaan. “Bayangkan pada awal minggu kita menerima Rp150.000 untuk kebutuhan kuliah. Setelah membeli makan, kita tahu uang berkurang, tetapi beberapa hari kemudian mungkin lupa berapa. Kalau mencatat saat transaksi terjadi, kita bisa mengecek kembali apa yang kita catat.” Terangkan bahwa demo memakai data contoh, bukan data rekening sungguhan.

0:45–1:30 · Solusi. “Terminal adalah jendela teks. Program menampilkan enam pilihan: mencatat masuk, mencatat keluar, melihat saldo, melihat riwayat, melihat kategori, dan keluar. Nominal harus bilangan Rupiah positif tanpa pemisah; kategori pengeluaran tidak boleh kosong.” Tunjukkan titik beda antara input 25000 dan format Rp25.000.

1:30–2:20 · Cara kerja. “Kita mulai dengan list kosong. Setiap transaksi adalah dictionary: tiga kolom bernama jenis, nominal, dan kategori. main memanggil modul pencatat untuk menambah satu item. Saldo tidak dicatat terpisah; dihitung dari daftar. Laporan membaca daftar yang sama tanpa menghapusnya. tampilan mengerjakan format, bukan matematika.” Tunjuk file sesuai perannya sambil memperlihatkan list sebelum dan sesudah append.

2:20–3:50 · Demo. Jalankan python3 main.py. Catat uang saku 150000 lewat menu 1. Di menu 2, masukkan 25.000 dan jelaskan penolakan sebelum kategori ditanya. Pilih 2 lagi, masukkan 25000 lalu Makan. Tampilkan menu 3 dan hitung keras-keras 150.000 dikurangi 25.000. Tampilkan 4 dan 5; tunjukkan dua baris riwayat tetapi hanya satu kategori biaya. Pilih 6 dan baca pesan penutupan.

3:50–4:35 · Refleksi. “Memisahkan file membuat tiap tugas lebih mudah diuji. Misalnya, saldo data kosong harus nol. Kelemahannya: catatan hilang setelah keluar, kategori membedakan huruf besar/kecil, dan tidak ada koreksi atau penghapusan transaksi. Ini prototipe belajar, bukan pengganti aplikasi bank. Perbaikan pertama kami adalah memuat dan menyimpan daftar dalam JSON, dengan validasi format dan penanganan file rusak.”

4:35–5:00 · Kesimpulan. “Data yang benar masuk, fungsi mengolah, lalu hasil ditampilkan. Kita bisa menjelaskan setiap angka pada demo dari daftar yang kecil.” Undang tanya jawab; sesuaikan pembagian waktu dengan ketentuan dosen dan kecepatan berbicara.

Alur dan pembagian peran

  1. Pembukaan: mulai dari pengalaman lupa mencatat.
  2. Masalah: kapan mahasiswa perlu melihat kembali pengeluaran?
  3. Solusi: menu terminal tanpa aplikasi tambahan.
  4. Cara kerja: tunjukkan empat file dan perubahan satu list.
  5. Demonstrasi: catat dua transaksi dan satu input salah.
  6. Kesimpulan: manfaat, tidak menyimpan data, dan rencana berikutnya.
  7. Tanya jawab: ulang pertanyaannya jika kurang jelas, lalu kaitkan jawaban ke kode.

Jika kebetulan bertiga: A membuka dan menjelaskan masalah; B menjelaskan file dan memandu demo; C menjelaskan keterbatasan, menutup, dan mengelola tanya jawab. Untuk jumlah lain, gabungkan atau pecah peran. Ini contoh, bukan pembagian kelompokmu.

Checklist dan rencana cadangan

24 pertanyaan latihan

Jawab keras-keras dulu. Buka pembahasan untuk memeriksa jawaban dan alasannya. Draf tidak disimpan.

1. Masalah apa yang diselesaikan?

Jawaban: Membantu mahasiswa mengingat transaksi dan menghitung saldo dari catatan.

Alasannya: Riwayat bisa diperiksa kembali, tetapi program tidak punya akses ke rekening.

2. Mengapa menggunakan terminal?

Jawaban: Supaya fokus belajar pada data, kondisi, dan fungsi sebelum membuat antarmuka grafis.

Alasannya: input dan print sudah cukup untuk interaksi pada implementasi ini.

3. Apa beda input, proses, output?

Jawaban: Input misalnya 25000, proses validasi dan hitung, output misalnya Saldo: Rp125.000.

Alasannya: Ketiganya adalah peran berbeda pada satu alur data.

4. Apa tugas main.py?

Jawaban: Menerima pilihan, memanggil fungsi, dan mengulang menu sampai keluar.

Alasannya: main mengatur urutan kerja, bukan menyimpan aturan format.

5. Apa tugas pencatat.py?

Jawaban: Memeriksa nominal/transaksi, menambah item, dan menghitung saldo.

Alasannya: Fungsi baca_nominal, tambah, dan saldo masing-masing mengerjakan hal itu.

6. Apa tugas laporan.py?

Jawaban: Menghasilkan teks riwayat dan pengelompokan biaya.

Alasannya: Riwayat membaca semua item; kategori melihat pengeluaran saja.

7. Apa tugas tampilan.py?

Jawaban: Mencetak menu dan mengubah bilangan ke teks Rupiah.

Alasannya: Fungsi ini tidak mengubah list transaksi.

8. Mengapa list dan dictionary?

Jawaban: List menjaga urutan catatan; dictionary memberi nama bidang per catatan.

Alasannya: Dengan demikian data[0] bermakna transaksi pertama, dan kunci nominal bermakna nilainya.

9. Mengapa tidak memakai float?

Jawaban: Rupiah dimodelkan sebagai bilangan bulat.

Alasannya: Tidak dibutuhkan pecahan dan int menghindari pembulatan float.

10. Dari mana Rp125.000 berasal?

Jawaban: 150000 dikurangi 25000.

Alasannya: Fungsi saldo mulai dari nol, menambah pemasukan, dan mengurangi pengeluaran.

11. Bolehkah saldo negatif?

Jawaban: Boleh.

Alasannya: Tidak ada aturan menolak transaksi yang lebih besar dari saldo.

12. Apa yang terjadi pada nominal 25.000?

Jawaban: Ditolak sebelum kategori diminta.

Alasannya: Validasi menerima digit ASCII, bukan titik, dan ValueError ditangkap oleh main.

13. Berapa batas nominal satu transaksi?

Jawaban: 1 sampai 999999999 Rupiah.

Alasannya: Setelah membuang nol depan, maksimum sembilan digit; tambah memeriksa rentang ulang.

14. Apa yang terjadi pada kategori kosong?

Jawaban: Ditolak, lalu kembali ke menu.

Alasannya: Kategori dibersihkan pada tepi sebelum dicek; append belum berlangsung.

15. Apakah Makan sama dengan makan?

Jawaban: Tidak pada versi ini.

Alasannya: Dictionary memakai nama asli sebagai kunci dan membedakan kapitalisasi.

16. Bagaimana dua biaya Makan digabung?

Jawaban: Tambah nominal baru ke total yang sudah ada.

Alasannya: get(nama, 0) menyediakan dasar 0 untuk kategori baru.

17. Mengapa while True tidak berjalan selamanya?

Jawaban: Pilihan 6 mencapai break.

Alasannya: break memutus loop terdekat, lalu fungsi selesai.

18. Apa gunanya penjaga __name__?

Jawaban: Memulai terminal hanya jika file dijalankan langsung.

Alasannya: Saat impor nama modul bukan __main__, jadi menu tidak berjalan.

19. Apakah laporan mengubah daftar?

Jawaban: Tidak.

Alasannya: riwayat membangun list teks; per_kategori memakai dictionary lokal.

20. Bagaimana menguji kasus tepi?

Jawaban: Cek list kosong, batas nominal, saldo negatif, dan kategori kosong.

Alasannya: Masing-masing menguji kondisi yang tidak terlihat di demo normal.

21. Berapa biaya waktu menghitung ulang saldo?

Jawaban: Linear terhadap jumlah transaksi (O(n)).

Alasannya: Satu kali kunjungan untuk tiap item; cocok untuk data sesi kecil.

22. Apakah data bertahan saat program ditutup?

Jawaban: Tidak.

Alasannya: List dibuat saat main mulai dan tidak ditulis ke penyimpanan.

23. Apa pengembangan pertama yang masuk akal?

Jawaban: Simpan ke JSON lalu muat kembali saat mulai.

Alasannya: JSON dapat merepresentasikan list/dictionary; perlu validasi, penanganan file hilang/rusak, dan aturan kapan menyimpan.

24. Apakah simulator menjalankan Python?

Jawaban: Tidak; ia meniru menu dan aturan menggunakan JavaScript.

Alasannya: Eksekusi Python sebenarnya terjadi saat interpreter lokal menjalankan main.py.
